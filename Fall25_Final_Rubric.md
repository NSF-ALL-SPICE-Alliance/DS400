---

## 1. GitHub Project, Collaboration & Workflow — *16 points*

### **A. Team Contributions (8 pts)**
- All team members push meaningful code to GitHub; commit history reflects real collaboration.  
- Shared workload and active participation in project work sessions (attendance unless excused).

### **B. Repository Quality (6 pts)**
- Public repository using R; clear folder structure; reproducible and well-documented scripts.  
- README includes:  
  - Project summary  
  - Data description or link  
  - **Three-sentence bios for each team member, with photo and link to GitHub/website/LinkedIn**

### **C. Research Question & Data Setup (2 pts)**
- Explicit, hypothesis-driven research question suitable for Bayesian analysis.  
- Appropriate dataset(s) included in the repo or linked in the README.

---

## 2. Analysis & Code Application — *8 points*

- Appropriate use of Bayesian methods covered in DS 400 (e.g., posterior inference, priors, Bayesian regression, predictive distributions, Bayes factors).  
- Clean, readable, well-commented code that supports the end-to-end workflow.  
- Models and diagnostics clearly tied to the hypothesis being tested.

---

## 3. Visualizations, Shiny App (Optional but Encouraged), & Results — *6 points*

- Clear and polished visualizations of posterior distributions, model uncertainty, predictions, etc.  
- If using Shiny: app demonstrates interactivity and communicates Bayesian results intuitively.  
- Results and interpretations correctly address the hypothesis and research question.

---

## 4. Final Presentation — *4 points*

**10 minutes + 1–2 minute GitHub walkthrough**

- Clear explanation of the background and hypothesis.  
- Summary of data, modeling approach, and Bayesian methods used.  
- Presentation of findings, visualizations, and uncertainty communication.  
- Brief walkthrough of GitHub repository (scripts, app, README) and clear conclusion.
